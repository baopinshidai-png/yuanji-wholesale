## 一、任务目标

参考「一手」小程序/APP（`#小程序://一手/QXmB5ojtjQQjCTm`），为**服装批发平台**做一套**大致可用的产品模板**：
客户（实体店主 / 网店 / 直播主播 / 微商）能在平台上直接拿到**源头一批档口货**。

判定标准（本轮的"完成"定义）：

1. 有一套**能跑起来、能点得通**的移动端原型（不是静态设计图）。
2. 覆盖批发平台核心业务闭环：`找款 → 看档口 → 选色码 → 进货单 → 结算 → 订单/售后`。
3. 有产品/技术方案文档，能直接交给开发团队评估工作量。
4. 有截图留档，醒来后 3 分钟能看懂做了什么。

## 二、参考平台调研结论（一手）

来源：App Store 官方介绍、界面新闻 2026-06 报道、官网 wlys.cn / yishouapp.com。

| 维度 | 一手的做法 | 对我们的意义 |
| --- | --- | --- |
| 定位 | 服装批发产业互联网平台，直达一级批发市场（十三行、沙河、白马、四季青、濮院、南油） | 平台角色 = 撮合 + 代采 + 履约，不是单纯商城 |
| 客户 | 实体店主、网店、微商、二批、主播 | 必须**店主认证**、拒绝散客 |
| 核心卖点 | 一件起批、单款单色打包价、一件代发 | 起批量/整手/代发是产品第一等公民 |
| 供给 | 2 万+ 供应链品牌、日上新 6000+ 款、买手选款 | 首页必须有"今日上新""买手推荐" |
| 履约 | 广州/杭州自营中转仓，90% 当日入仓即发，慢必赔、断货赔付 | 商品卡要打"现货/24H 发/赔付"标签 |
| 工具 | 以图搜款、一键下载素材、批量下单、加购分组、直播拿货、拼单社群 | 差异化功能清单，见方案文档第三部分 |
| 上游 | 货款日结担保、托管式经营（平台代客服/售后） | 后续要做**商家端**，本轮先不做 |

结论：一手的产品结构 = **商城骨架（档口→商品→进货单→订单）+ 批发专属规则（起批、色码、代发、赔付）+ 内容化选款（上新、买手、直播）**。
本轮原型按这个结构搭。

**② 顺手抓到并修掉一个真 Bug：接口层返回值和页面调用方式不一致**
`utils/api.js` 的 mock 助手原来返回同步值（`return v`），但
`pages/home/index.js` 用 `api.getHome().then(...)`、`pages/list/index.js` 用 `api.getGoodsList(...).then(...)`，
运行时报 `... .then is not a function`。后果不只是报错：**市场列表页的商品列表渲染不出来**
（截图非空像素 28.3% → 修复后 63.7%，商品卡 12 个正常出来）。
修法：mock 层统一返回 Promise（助手改名 `reply()`），与文档里写的「接后端时换成 `wx.request`、页面代码不用动」保持一致；
已确认全项目只有这两个页面调用 `api.*`，且都是 `.then` 写法。

## 四点五、第 12 轮进展（分账：平台代收 → 按档口结算，防二清）

**① 为什么做这个**：钱先到平台商户号、再私下转给档口 = 二次清算，是监管红线。
正解是用微信支付的**分账**能力，收款时就按订单把档口货款分给档口自己的商户号/微信号。

**② 后端新增** `outputs/yuanji-server/src/profitsharing.js`
- 分账接收方管理：`POST /admin/stalls/{id}/settle-account`（绑档口商户号/微信号，真支付模式会同步调
  `/v3/profitsharing/receivers/add` 登记）。
- 结算规则：档口货款 = 订单实付 − 平台佣金（`PLATFORM_FEE_RATE`，默认 5%），金额按分计算。
- 支付成功后**自动分账**（`POST /v3/profitsharing/orders`，`unfreeze_unsplit` 解冻剩余资金）；
  可 `PROFIT_SHARING_ON_PAY=0` 关掉。
- **退款自动分账回退**（`/v3/profitsharing/return-orders`），避免"钱已分给档口又全额退给买家"的窟窿。
- 档口**没绑结算账户**时资金挂账（`hold`），补绑后定时任务自动补分账；分账结果回调
  `POST /pay/profit-sharing-notify` 也会回写状态。
- 平台侧查询：`GET /orders/{id}/settle`、`GET /admin/settlements`（已分账/挂账金额与订单明细）、`POST /admin/settle/run`。

**③ 验证** `work/test-settle.ps1`（临时 3200 端口实例，独立数据库）
- 绑定档口 s1 的结算账户（模拟）→ 买家下单 ¥39.9 → 付款 → **分账成功：档口得 3790 分（¥37.90）、平台佣金 200 分（¥2.00）、费率 5%**。
- 申请退款 → 订单变「已退款」→ 分账状态变 **`returned`（已回退）**。
- 平台总览接口返回费率、挂账/已分账统计。**全部通过**。

**④ 注意 / 待办**
- 商户平台要开通「分账」产品并设置最大分账比例（默认 30%，档口货款比例高时要提前调高，否则报 `PARAM_ERROR`）。
- 还没做：分账单对账（`/v3/profitsharing/bills`）、档口结算账户的入驻审核流程、商家端结算页。
- 小程序端无需改动（分账是平台与档口之间的资金流），所以体验版仍是 1.0.3。

## 三点五、真机实测新增的关键结论（第 2 轮）

通过 Computer Use 接管了微信里的小程序窗口（`WeChatAppEx.exe` → 「一手服装批发」），逐页实测了
**专场首页 / 分类 / 进货车 / 我的 / 市场列表页 / 商品详情页**，挖到 9 条硬规则，其中最重要的 5 条：

1. **小程序是精简版**：底部只有 4 个 Tab（专场/分类/进货车/我的），**没有直播**；商品详情只有 3 个页签（商品/档口/详情）。
2. **价格闸门**：未登录/未认证只显示「建议零售价」，拿货价要认证后才可见（页面常驻 `登录注册，完成认证可看拿货价`）。
3. **档口挂阶梯满减**：从「满699减5」到「满30000减1050」共 18 档，挂在档口上，商品详情里能展开。
4. **发货时效承诺**：`广州发货` + `当前下单，09月21日未发可取消` + `24H极速发` 标签。
5. **退换货按品类开关**：`不支持退货` 的品类说明为「特价让利商品、内衣、童装、鞋包配等部分品类不支持无理由退货」。

另外实测确认：商品卡有 `今日新款` 角标 / 视频角标 / `今日已拼N件` / `沙河 | 满699减5`，
并且支持 **长按商品卡搜相似款**；首页流量入口是 **市场名**（沙河、杭州、濮院、南油、十三行、中纺、金马市场…）。
