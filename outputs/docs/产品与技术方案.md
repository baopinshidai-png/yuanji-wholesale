# 服装批发平台 · 产品与技术方案（v1）

> 面向对象：你 + 未来接手的开发团队。
> 依据：「一手」小程序/APP 真机实测（见 `一手小程序-真机实测记录.md`）+ 已交付的小程序模板（`yuanji-miniprogram/`）。
> 结论先行：**第一版做「找货 + 拿货 + 履约」闭环，不做 C 端零售、不做复杂促销引擎。**

---

## 一、产品定位

| 项目 | 内容 |
| --- | --- |
| 一句话 | 让服装店主在手机上从**源头一批档口**直接拿货的批发平台 |
| 目标用户 | 实体服装店店主、网店/直播主播、微商、二批档口、工作室 |
| 供给 | 一级批发市场档口 / 产业带工厂（沙河、十三行、杭州四季青、濮院、南油…） |
| 平台角色 | 撮合 + 代采 + 质检履约 + 售后（不是单纯商城） |
| 核心价值 | 一件起批、单款单色打包价、现货 24H 发、支持退换、比二批便宜 |
| 明确不做（第一版） | C 端零售、复杂营销玩法、跨境、自建物流 |

## 二、角色与权限

| 角色 | 端 | 权限要点 |
| --- | --- | --- |
| 游客 | 小程序 | 只能浏览「建议零售价」，看不到拿货价 |
| 登录用户 | 小程序 | 可加进货车、看订单；**仍未认证则看不到拿货价** |
| 认证店主（客户） | 小程序 | 解锁拿货价、下单、售后、素材下载、订阅档口 |
| 档口商家 | 商家端（第二期） | 上架、开单、配货、查看结算 |
| 平台运营 | 后台（第二期） | 审核档口/商品、买手选款、活动、售后仲裁、结算 |

> **关键规则（实测自一手）**：价格闸门 = **登录 + 店主认证**，两道都要过。未认证时价格位显示「建议零售价」并挂「登录看拿货价」。

## 四、核心业务规则（可执行的规则定义）

### 4.1 价格体系（三层）

```
建议零售价（对游客展示，划线价）
     ↓ 认证后可见
拿货价（批发价，单款单色打包价）
     ↓ 参与活动
活动价（如「膨胀立减 15」「助力预估价」）
```

- 商品表需存：`suggest_price`、`cost_price`（拿货价）、`activity_price`（可空）
- 价格展示由**服务端按用户认证状态返回**，不要在前端做隐藏（否则抓包可看）

### 4.2 起批与规格

- 默认 **单款单色 1 件起批**；支持「整手拿货」（如 3 件/手）作为可选字段
- SKU 维度：`颜色 × 尺码`，颜色需带色值（前端展示色块）

### 4.3 满减与红包

- **阶梯满减挂在档口上**，每档位形如 `满399减5` … `满30000减1050`
- 红包/券需「领取」动作，有门槛与有效期（实测：满339减30，168 小时有效）
- 结算时先算档口满减，再叠加红包/券，最后 + 运费

### 4.4 履约与时效

| 规则 | 定义 |
| --- | --- |
| 现货标记 | 商品可打 `24H发货` 标，承诺 24 小时内发出 |
| 未发可取消 | 下单后到约定时间未发货，用户可自助取消（实测：页面直接提示「09月21日未发可取消」） |
| 慢必赔 | 超时未发赔付（建议按订单金额比例，封顶） |
| 断货赔付 | 档口断货需赔付 + 全额退款 |
| 拆单 | **按档口拆单**，不同档口分别发货与结算 |

### 4.5 售后

- 商品维度带 `退货策略` 字段：`支持7天无理由` / `不支持（+原因）`
- 实测文案：*特价让利商品、内衣、童装、鞋包配等部分品类不支持无理由退货*
- 支持退货的商品需保持吊牌完整

### 4.6 会员

- 按「当月拿货额」升级（实测：普通会员 V1 → 白银会员，门槛 2000 元）
- 权益：淡季保级、会员专享、VIP 客服、包邮特权、拿货价额外折扣

## 六、后端接口清单（MVP）

> 统一前缀 `/api/v1`，鉴权：`Authorization: Bearer <token>`（`wx.login` → code2session 换 token）。

**用户与认证**
- `POST /auth/login`（code → token）
- `POST /auth/phone`（getPhoneNumber 解密绑定手机号）
- `GET /user/profile`
- `POST /user/cert`（提交店主认证） / `GET /user/cert`（认证状态）

**商品与档口**
- `GET /home`（首页聚合：礼包、榜单、市场、运营卡、频道）
- `GET /markets` / `GET /categories`
- `GET /goods?market=&category=&sort=&filter=&page=`
- `GET /goods/{id}`（详情；**按认证状态返回价格**）
- `GET /stalls` / `GET /stalls/{id}`
- `GET /search?kw=` / `POST /search/image`（以图搜款，二期）
- `POST /subscriptions` / `DELETE /subscriptions/{stallId}` / `GET /subscriptions`
- `POST /favorites` / `DELETE /favorites/{goodsId}` / `GET /favorites`

**交易**
- `GET /cart` / `POST /cart` / `PATCH /cart/{id}` / `DELETE /cart/{id}`
- `GET /coupons` / `POST /coupons/{id}/claim` / `GET /my/coupons`
- `POST /orders/preview`（结算试算：满减+红包+运费）
- `POST /orders`（下单，按档口拆单）
- `POST /orders/{id}/pay`（微信支付统一下单）/ `POST /pay/notify`
- `GET /orders?status=` / `GET /orders/{id}`
- `POST /orders/{id}/cancel` / `POST /orders/{id}/confirm`

**售后与物流**
- `POST /aftersales` / `GET /aftersales` / `POST /aftersales/{id}/arbitrate`（平台）
- `GET /orders/{id}/logistics`（对接快递 100 / 菜鸟面单）

## 七、技术选型建议

| 层 | 建议 | 说明 |
| --- | --- | --- |
| 小程序 | 原生小程序（当前模板即原生）或 Taro/uni-app | 若将来要出 App，建议一套代码多端 |
| 后端 | Spring Boot / NestJS / Go 任选 | 订单与结算用强事务数据库 |
| 数据库 | MySQL 8 + Redis | Redis 缓首页聚合与榜单 |
| 对象存储 | 腾讯云 COS / 阿里云 OSS + CDN | 图/视频量大，必须 CDN + 图片处理 |
| 搜索 | MySQL 模糊查起步；量大接 ES | 以图搜款二期接向量检索 |
| 支付 | 微信支付 JSAPI + 分账 | 平台代收再结算需分账，避免二清 |
| 物流 | 快递 100 / 菜鸟开放平台 | 面单 + 轨迹回传 |
| 消息 | 小程序订阅消息 | 发货、超时未发、退款进度 |

## 八、合规与资质（提前准备）

1. **主体资质**：营业执照 + 小程序企业主体认证；涉及在线交易建议办 EDI/ICP 相关备案。
2. **微信支付**：申请商户号；平台代收再结算给档口需走**分账**或与支付机构合作，避免二清风险。
3. **类目资质**：服饰类目一般需要质检报告/品牌授权（如涉及品牌商品）。
4. **拒绝散客的表达**：注册/认证环节写明「仅向服装从业者提供批发价」。
5. **售后规则公示**：不支持退货的品类必须在商品页明确说明原因。
6. **个人信息**：手机号、地址需隐私政策 + 最小必要采集（模板登录页已含协议勾选）。

## 十、我们与「一手」的差异建议

**要照抄的**：4 个 Tab 结构、价格闸门、档口阶梯满减、按档口拆单、24H 发货与未发可取消、退货策略标注、商品卡角标体系、日更上新的运营节奏。

**可以做得更好的**：
1. **档口信用分**：把发货率、超时赔付、退货率做成可视化信用分（一手只露评分）。
2. **以图搜款 + 相似款**（一手已支持，我们做成差异化体验）。
3. **跨档口凑单提示**：按满减门槛提示还差多少，帮店主省运费。
4. **代发对接**：一键同步到抖音/快手/视频号小店。

**不要做的**：MVP 阶段不做直播、复杂会员等级、SaaS 工具矩阵——一手是 10 年积累，我们先把「拿货闭环」跑通。
