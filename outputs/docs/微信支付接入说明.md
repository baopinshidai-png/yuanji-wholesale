## 二、你要准备的 5 样东西

1. **微信支付商户号（mchid）**：企业或个体工商户可申请，需营业执照 + 法人信息，审核通常 1~5 个工作日。
2. **关联小程序 AppID**：在商户平台「产品中心 → AppID 账号管理」把小程序 AppID 关联上（否则下单会报 appid 与 mchid 不匹配）。
3. **APIv3 密钥**：商户平台「账户中心 → API 安全」设置，32 位字符串，用于回调解密。
4. **商户 API 证书**：下载后得到证书序列号（serial）与 `apiclient_key.pem`（私钥），用于请求签名。
5. **回调地址**：必须是 **HTTPS 公网域名**，例如 `https://api.你的域名.com/api/v1/pay/notify`（微信要能访问到）。

## 三、配置（环境变量）

| 变量 | 说明 |
| --- | --- |
| `WECHAT_APPID` | 小程序 AppID（同时也用于 `code2session` 登录） |
| `WECHAT_SECRET` | 小程序 AppSecret（登录用） |
| `WECHAT_MCHID` | 微信支付商户号 |
| `WECHAT_PAY_SERIAL` | 商户 API 证书序列号 |
| `WECHAT_PAY_PRIVATE_KEY` | `apiclient_key.pem` 的内容或文件路径 |
| `WECHAT_PAY_APIV3_KEY` | APIv3 密钥（32 位） |
| `WECHAT_PAY_PLATFORM_CERT` | 微信支付平台证书（用于回调验签，PEM 内容或路径） |
| `WECHAT_PAY_NOTIFY_URL` | 支付回调地址（HTTPS） |
| `TOKEN_SECRET` | 小程序登录 token 签名密钥（上线必改） |

配置示例（Windows PowerShell）：

```powershell
$env:WECHAT_APPID='wx1234567890abcdef'
$env:WECHAT_SECRET='小程序 AppSecret'
$env:WECHAT_MCHID='1600000000'
$env:WECHAT_PAY_SERIAL='4C1E2A...'
$env:WECHAT_PAY_PRIVATE_KEY='C:\yuanji\certs\apiclient_key.pem'
$env:WECHAT_PAY_APIV3_KEY='32位APIv3密钥'
$env:WECHAT_PAY_PLATFORM_CERT='C:\yuanji\certs\wechatpay_platform.pem'
$env:WECHAT_PAY_NOTIFY_URL='https://api.你的域名.com/api/v1/pay/notify'
$env:TOKEN_SECRET='换成一串随机字符串'
node server.js
```

> 证书文件**不要提交到代码仓库**。建议放服务器 `/etc/yuanji/certs/`，用环境变量或密钥管理服务注入。

## 四、联调步骤

1. 启动后端（配好上面的变量），用 `POST /api/v1/auth/login` 拿 token。
2. 小程序里登录 → 认证 → 加购 → 提交订单 → 订单列表点「去付款」。
3. 后端会返回 `{ mode: 'wechat', payParams }`，小程序调起微信支付面板。
4. 支付成功后微信回调 `/api/v1/pay/notify`：后端验签 → 解密 → 订单置为「待发货」。
5. 回调丢失时，可在订单接口 `GET /api/v1/orders/{id}/pay-status` 主动查单对账。

**先用 1 分钱商品或 0.01 元订单压测一遍**，确认回调、状态流转、查单都对，再上真实金额。

## 五、常见错误

| 现象 | 原因 |
| --- | --- |
| `SIGN_ERROR` / 401 | 私钥、证书序列号、签名串拼错（换行符必须严格是 `\n`） |
| `PARAM_ERROR: appid and mchid not match` | 商户号没关联该小程序 AppID |
| 回调一直收到 401 | 没配平台证书，或平台证书过期（微信平台证书需定期更新） |
| `ORDERPAID` | 重复支付，需按订单号做幂等判断（当前已校验订单状态） |
| 回调收不到 | 回调地址不是 HTTPS 公网地址，或没在商户平台配置回调域名 |
| 手机端报「商户参数格式错误」 | 小程序后台没绑定该商户号 / 未签约 JSAPI 支付 |

## 七、退款与自动关单（已实现，配置即可用）

**退款**

| 环节 | 说明 |
| --- | --- |
| 入口 | 小程序订单列表 / 订单详情 →「申请退款」（可填原因） |
| 接口 | `POST /api/v1/orders/{id}/refund`，body：`{ reason, amount? }`（不传 amount 就是整单退） |
| 微信侧 | `POST /v3/refund/domestic/refunds`，`out_refund_no` 用 `R+订单号`，`notify_url` 自动派生为 `…/pay/refund-notify` |
| 状态流转 | 未支付订单不可退；申请后订单变 `refunding`（退款中）→ 回调成功后变 `refunded`（已退款）；退款失败则回到 `unship` |
| 对账 | `GET /api/v1/orders/{id}/refund-status` 主动查退款单 |
| 未配商户号 | 演示模式：直接标记为「已退款」，方便演示流程 |

**超时未支付自动关单**

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `ORDER_TIMEOUT_MIN` | 30 | 下单后多少分钟未支付自动关闭（可写小数，0.05 = 3 秒） |
| `SWEEP_INTERVAL_SEC` | 60 | 扫描间隔（秒） |
| `ADMIN_TOKEN` | 空 | 配置后可调 `POST /api/v1/admin/sweep` 手动触发一次关单（请求头 `x-admin-token`） |

真支付模式下，关单会同时调用微信 `POST /v3/pay/transactions/out-trade-no/{no}/close`；
关掉的订单会写入 `cancelReason: 超时未支付，系统自动关闭`。

自测脚本：`work/test-refund-close.ps1`（会临时起一个 3100 端口的实例，把超时设成 3 秒来验证关单）。

## 八、分账（平台代收 → 按档口结算，避免二清）

**为什么必须做**：钱先收到平台商户号、再私下转给档口，属于「二次清算」，是监管红线。
正确做法是用微信支付的**分账**能力：收款时就冻结对应金额，按规则直接分给档口自己的商户号/微信号。

**流向**

```
买家付款 → 平台商户号 → （按订单）分账给档口 → 平台留佣金
                ↓ 退款时
            分账回退 → 原路退回买家
```

**接口**

| 用途 | 接口 |
| --- | --- |
| 给档口绑定分账接收方 | `POST /api/v1/admin/stalls/{id}/settle-account`（body：`{type:'MERCHANT_ID'或'PERSONAL_OPENID', account, name?}`，需 `x-admin-token`） |
| 支付成功后自动分账 | 支付回调里自动触发（可用 `PROFIT_SHARING_ON_PAY=0` 关掉） |
| 查看某单结算 | `GET /api/v1/orders/{id}/settle` |
| 手动补分账 | `POST /api/v1/admin/settle/run`（档口后补绑账户后用） |
| 分账总览 | `GET /api/v1/admin/settlements`（已分账/挂账金额与订单明细） |
| 分账结果回调 | `POST /api/v1/pay/profit-sharing-notify` |
| 退款自动回退 | 退款成功后自动调 `/v3/profitsharing/return-orders` |

**规则**

- 平台佣金比例 `PLATFORM_FEE_RATE`（默认 0.05 = 5%），档口货款 = 订单实付 − 平台佣金。
- 档口**没绑结算账户**时：钱留在平台，订单结算状态记为 `hold`（挂账），档口补绑后定时任务会自动补分账。
- 未配商户号时是 mock：按同样的规则算出分账计划并标记成功，方便核对金额与流转。
- 定时任务每 60 秒扫描一次待分账订单（`hold` / `failed` / 未分账的已支付订单）。

**平台侧还要做的**

- 商户平台开通「分账」产品，并设置**最大分账比例**（默认上限 30%，档口货款比例高时要提前调高，否则会报 `PARAM_ERROR`）。
- 维护档口的结算账户（相当于商家入驻资料），并在每次变更后重新调用接收方登记接口。
- 对账：定期拉 `/v3/profitsharing/bills` 分账单与平台流水核对。

**自测**：`work/test-settle.ps1`（绑定档口账户 → 下单付款 → 分账成功 → 退款 → 分账回退，全流程校验金额）。
