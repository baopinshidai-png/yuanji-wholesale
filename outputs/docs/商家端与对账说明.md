# 商家端（档口工作台）与对账说明

> 更新时间：2026-09-11　适用：后端 `outputs/yuanji-server` + 小程序 `pages/stall-console`

## 一、档口工作台是什么

给合作档口用的**最小可用商家端**：档口不用装新 App，在小程序里用平台发的邀请码进入，就能
**看待发货订单 → 一键发货（填运单号）→ 管自己商品的上下架 → 看今日经营数据**。

入口：小程序「我的 → 档口工作台（商家端）」。

## 二、邀请码怎么发

档口不能自己注册（避免散客/假档口），由平台运营发码：

```powershell
# 需要后端配了 ADMIN_TOKEN
curl -X POST http://127.0.0.1:3000/api/v1/admin/stalls/s1/invite -H "x-admin-token: <你的ADMIN_TOKEN>"
# → { "stallId": "s1", "stallName": "HERS", "code": "S1-2026" }
```

档口在「档口工作台」输入邀请码 → 换到 7 天有效的档口 token（与买家登录态分开存，互不影响）。

> 本地演示：开发库已预置 `S1-2026` ~ `S8-2026`（档口 ID 大写 + `-2026`），
> 重新预置可执行 `node work/seed-stall-codes.mjs`（**先停掉后端再执行**，否则会被内存里的旧数据覆盖）。

## 三、档口能做什么

| 功能 | 说明 |
| --- | --- |
| 今日经营数据 | 今日订单数、今日货款、待发货数、已分账金额 |
| 待发货 / 已发货 / 全部订单 | 只显示**本档口**的订单，含商品、规格、收货信息、买家备注 |
| 一键发货 | 弹窗填运单号（可留空自动生成），发货后买家侧订单立即变「待收货」 |
| 商品上下架 | 下架后**买家列表/搜索立刻查不到**这件商品（后端过滤） |
| 自助上架商品 | 「商品 → 上架新商品」：传图 + 填标题/拿货价/建议零售价/颜色/尺码 → 买家立即可见；自己上架的商品可再编辑 |
| 结算与资质 | 「结算与资质」：填联系人/电话/城市/营业执照号 + 结算账户（商户号或微信号）→ 提交平台审核；**审核通过后货款才会分账到账** |

## 四、对应的后端接口

| 用途 | 接口 | 鉴权 |
| --- | --- | --- |
| 平台发邀请码 | `POST /admin/stalls/{id}/invite` | `x-admin-token` |
| 档口登录 | `POST /stall/login` `{code}` | 公开（凭邀请码） |
| 档口信息 | `GET /stall/me` | 档口 token |
| 经营数据 | `GET /stall/stats` | 档口 token |
| 档口订单 | `GET /stall/orders?status=unship|shipped|all` | 档口 token |
| 发货 | `POST /stall/orders/{id}/ship` `{logistics}` | 档口 token |
| 商品列表 | `GET /stall/goods` | 档口 token |
| 上下架 | `POST /stall/goods/{id}/toggle` `{off:true|false}` | 档口 token |
| 新建商品 | `POST /stall/goods` `{title, price, suggestPrice?, goodsNo?, colors, sizes, imgUrl}` | 档口 token |
| 编辑商品 | `POST /stall/goods/{id}/update`（只能改自己上架的） | 档口 token |
| 图片上传 | `POST /upload` `{data:<base64>, contentType, filename}` → `{url}` | 买家或档口登录态 |
| 查看资料/结算状态 | `GET /stall/profile` | 档口 token |
| 提交资料/结算账户 | `POST /stall/profile` | 档口 token |
| 平台查看待审 | `GET /admin/stall-profiles?status=pending` | `x-admin-token` |
| 平台审核 | `POST /admin/stalls/{id}/review` `{approve, note}` | `x-admin-token` |

档口 token 用同一个签名密钥签发（payload 里是 `stallId`），7 天有效。

## 五、对账（每天要做的钱账）

### 1. 平台内部账单（不依赖微信，随时可看）

| 用途 | 接口 |
| --- | --- |
| 账单汇总 | `GET /admin/bills/summary?date=YYYY-MM-DD` |
| 导出明细 CSV | `GET /admin/bills/export?date=`（写入 `data/bills/local-<日期>.csv`，同时返回内容） |

汇总字段：`paid`（已收款笔数与金额）、`refunded`（退款笔数与金额）、
`settle.settledCount / stallShare / platformFee / holdAmount`（已分账笔数、档口货款、平台佣金、挂账金额）、
`byStall`（按档口拆分的订单数与金额）。

明细 CSV 字段：订单号、下单时间、支付时间、档口、状态、实付金额、退款金额、档口货款、平台佣金、分账状态。

### 2. 微信支付官方账单（需要商户号）

```powershell
POST /api/v1/admin/bills/download   {"date":"2026-09-11","type":"trade"}     # 交易账单
POST /api/v1/admin/bills/download   {"date":"2026-09-11","type":"fundflow"}  # 资金账单
```

- 走微信 `/v3/bill/tradebill`、`/v3/bill/fundflowbill`，拿到 `download_url` 后下载 CSV，存到 `data/bills/`。
- 微信账单**不是实时生成**的：当天账单一般次日才可下载，代码里已做"还没生成"的兜底提示。
- 未配商户号时接口会明确返回 mock 提示，不会假装成功。

### 3. 建议的日结流程

1. 每天上午拉前一天 `summary` → 和微信交易账单的收款金额核对。
2. 有差异时看 `byStall` 与分账状态：`hold` 金额通常是「档口没绑结算账户」导致的挂账。
3. 档口补绑结算账户后，跑一次 `POST /admin/settle/run` 把挂账补分账。
4. 退款单要同时核对：退款金额、分账是否已 `returned`。

### 4. 逐笔差异比对（已实现）

- `POST /admin/bills/reconcile {date}` 会下载当天微信交易账单、**按表头解析成逐笔记录**，与本地已收款订单比对，输出三类差异：
  | 差异类型 | 含义 | 处理 |
  | --- | --- | --- |
  | `missingInWechat` | 本地已收款、微信账单无记录 | 多为掉单/未真正支付成功，需查支付状态并补单或取消 |
  | `missingLocal` | 微信有收款、本地无订单 | **最严重**（漏单），要立即补单并检查回调 |
  | `amountMismatch` | 同一单号金额不一致 | 核对优惠/分账口径 |
- 结果写入 `data/bills/reconcile-<日期>.json`，运营后台「对账 → 看逐笔差异」直接看；
  有差异会写入提醒（运营后台总览可见）。
- 配 `NOTIFY_WEBHOOK`（企业微信/钉钉机器人地址）后，**有差异自动推送一条消息**；
  未配商户号时只生成本地快照并标记 `skipped`。

## 七、商品图片上传（含上线换 CDN）

- 小程序端流程：`wx.chooseMedia` 选图 → `getFileSystemManager().readFileSync(path, 'base64')`
  → `POST /upload` → 拿到 `url` → 存进商品 `imgUrl`。
- 服务端：`src/uploads.js` 按内容 SHA1 命名存到 `UPLOAD_DIR`，静态路由 `/uploads/<文件名>` 返回，
  带一年 `cache-control`；同一张图重复上传不会产生副本。
- 商品图字段统一：内置图是 `/images/goods/gN.jpg`，档口上传图是绝对 URL；
  小程序用 `utils/image.js` 统一成可直接渲染的 `imgUrl`，页面只认 `imgUrl` 一个字段。
- **上生产**：把 `saveImage` 换成 COS/OSS 直传（保留同样的返回值），`ASSET_BASE_URL` 填 CDN 域名即可，
  业务代码与小程序都不用改。

## 八、结算账户与资质审核（分账的前置条件）

**为什么要审核**：分账是「平台代收 → 打给档口」，账户信息填错就会把钱打给错误的主体，
所以档口提交的资料**必须平台审核通过后**才参与分账。

**流程**

1. 档口在「结算与资质」填：联系人、联系电话、所在城市、营业执照号（选填）、
   结算账户类型（商户号 / 微信号）、账号、账户名称。
2. 提交后档口状态变 `pending`（待审核），结算账户标记为 `pending`。
3. 平台审核：`POST /admin/stalls/{id}/review` `{approve:true, note}`；
   通过时会自动调用微信 `receivers/add` 登记分账接收方（mock 模式只记录）。
4. 审核通过的档口，订单分账正常执行；**未审核/被驳回**的档口，货款自动**挂账**（`hold`），
   原因写明「档口结算账户待平台审核」或「档口未绑定结算账户」。
5. 审核通过后跑一次 `POST /admin/settle/run`，之前挂账的订单会自动补分账。

**验证脚本**：`work/test-stall-profile.ps1`
（提交资料 → 未审核时分账挂账 → 平台通过 → 补分账成功：档口 3790 分 / 平台佣金 200 分）。
